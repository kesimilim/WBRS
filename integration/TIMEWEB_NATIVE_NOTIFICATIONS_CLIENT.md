# Native notifications client

Home's actual bell opens `TimewebNotificationsPage` on the same TimewebAppRuntime/session. Existing approved family photograph, glass panels and CLRS elements remain; at 360 px the notification content uses left three quarters, with natural full-width large-text fallback. Historical read/createdAt null remain unknown, not fake unread/clock values. Generic localized labels expose no source IDs/private message text. All 23 bundled catalogs already contain these labels; no translation/provider/catalog changes.

The new auth part uses the shared four-flight GET budget, abort/drain and native owner/epoch guard, no-store JSON <=64 KiB. DTO keys/types/source IDs are strict. Opaque cursors bind current client/UID/limit, stay in RAM and keep original 300s expiry. A sparse page retains an explicit Load more action and never claims terminal no-results. The rendered window is capped at 300 records, retaining the next server cursor as older pages replace newest rows. No automatic pagination loop or mark-read mutation.

Each center tap first reads the original `/me/notifications/{id}` source and current target. Off-page personal chats open through a tiny `openExistingChat` seam: exact ID + fresh current messages GET + original existing journal, not a fabricated list DTO or new chat POST. Meeting targets use existing current meeting detail with its further current guards. Destination wrappers and center retain the original lease even if B becomes active before their first build; cleanup removes only their own route, never a newer B route. Invalidated fields/cursors are cleared immediately.

Native main subscribes FCM foreground/opened/initial transport only in its Timeweb branch. It never calls Firebase Auth/Firestore/global identity, legacy deep links or legacy notification destination. The worker's exact six-field payload is validated; `notificationId:e:<event>` is resolved with fresh native GET and matched against recipient/current target. No unproven resource fallback. Foreground additionally reads actual current preferences and suppresses disabled messages/meetings/sound. Body is generic localized text, no private message preview. Local tap persists only source ID/recipient UID in the OS notification payload, re-resolves on tap and checks the current lease. One latest RAM signal is bounded; logout clears old queued state/OS notifications and late A responses cannot display or navigate for B. Provider delivery itself is not proven by these mocks.
