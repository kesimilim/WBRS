# Сборка CLRS для Timeweb

Нужны Flutter **3.32.5** (Dart 3.8), JDK 17, Android SDK с build-tools 35.0.0 и NDK 26.1.10909125. Установите `ANDROID_SDK_ROOT` и при необходимости `FLUTTER_BIN`.

`config/timeweb.production.json` содержит публичные настройки нативного клиента из проверочной сборки 68: API, идентификатор миграции и переключатели функций. Паролей и серверных ключей здесь нет. При смене API или миграционного идентификатора нужна отдельная проверка клиента. Наличие этих настроек не подтверждает завершение миграции или работоспособность почты восстановления.

## Проверочный APK

```sh
./BUILD_APK.command --build-number 69
```

Номер 69 — пример следующего номера после локальной сборки 68. Перед магазинным выпуском сравните его с последним номером в действующей карточке RuStore. Номер задаётся явно, чтобы случайно не выпустить старый `+40` из `pubspec.yaml`.

Результат: `build/delivery/qa/`, APK с пометкой **QA** и JSON с коммитом, SHA-256, конфигурацией и сертификатом. Это проверочная подпись, не готовый выпуск RuStore. `--dry-run` показывает команду без сборки и сетевых запросов.

## Кандидат для RuStore

Используется **исходный ключ опубликованного приложения**, новый ключ не создаётся. В приватном файле вне Git сохраните стандартные настройки `storeFile`, `storePassword`, `keyAlias`, `keyPassword`. Относительный `storeFile` считается от каталога этого файла.

```sh
export CLRS_ANDROID_SIGNING_PROPERTIES=/private/path/android-signing.properties
export CLRS_STORE_CERT_SHA256=sha256_сертификата_действующего_apk_из_магазина
./build_android_release.sh --build-number 69
```

Скрипт требует сохранённые в Git изменения, исходный ключ и SHA-256 сертификата действующей версии. Отсутствующие настройки, debug-подпись или другой сертификат останавливают сборку/выдачу кандидата. Данные подписи не выводятся в команду и не передаются через Dart defines. Готовый кандидат попадает в `build/delivery/store/`. Нельзя публиковать промежуточный APK из `build/app/outputs/`, если проверка завершилась ошибкой.

Одна подпись ещё не закрывает приёмку: нужны проверка обновления поверх магазинной версии, сценарии приложения, сверка данных/сервера, юридические документы и отдельная отправка в RuStore. Сам скрипт ничего не загружает в магазин.

## GitLab

CI использует фиксированный образ Flutter 3.32.5. Автоматически запускаются проверки старта, изоляции backend и уведомлений. Полный прогон и сборки запускаются отдельно. Для сборки задайте `CLRS_BUILD_NUMBER`. Магазинная задача доступна только на защищённых ветках/тегах; ключ и properties храните в защищённых секретах CI, а не в переменных ручного запуска.

Старая шаблонная выкладка на Firebase Hosting и пустые задачи Google Play убраны: публикация исходников не должна переключать сервер или выкладывать другой backend. Последняя локально проверенная сборка до этих изменений — **68**, исходный коммит `5703c2889f9fe30e86b65d4a20d06a85796221dc`. Этот документ не объявляет CI, подпись RuStore или публикацию выполненными.
