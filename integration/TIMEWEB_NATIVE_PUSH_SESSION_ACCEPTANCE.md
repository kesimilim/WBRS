# Atomic native push session acceptance

The session change adds four push-token hooks inside the existing native auth transaction: successful refresh rebinds ciphertext to the new SID after session INSERT; normal logout clears that exact SID; all-session logout clears the owner; authenticated old refresh replay clears the affected device before committed rejection. Missing push key retains the prior auth path and grants. A configured invalid key refuses construction; valid configured key adds only token SELECT/UPDATE to the strict auth grant contract. Provider-database permission remains the existing declared SELECT/INSERT/UPDATE role. No DDL, password/account update or Firebase call is added.

One actual retained local MySQL 8.4.4 Unix-socket case passed first run in 0.506 seconds with CA/hostname TLS, actual SQL principal and normal fixture password login through NativeAuthService. It exercised Push HTTP with the same runtime store: real register COMMIT with lost ACK and restart original lookup; refreshed SID ciphertext and historical original receipt; corrupted ciphertext causing actual logout rollback without session revocation; normal/all-session logout and old refresh replay; fresh owner B registration of the released physical FCM token. Missing provider claimed no outbox row; a revoked recipient caused no provider send. Only this new fixture outbox priority was pinned, leaving earlier fixture queue unchanged. Same retained datadir was started once and stopped after the case; no init/clone/reset, TCP, Timeweb, real Google request or migration customer rows. This proves local transaction/SQL/session behavior, not stand deployment or device delivery. The private proof binds exact tested sources; client coordinator must still treat old-SID receipts as historical and retain original UNKNOWN intents without repeat POST.
