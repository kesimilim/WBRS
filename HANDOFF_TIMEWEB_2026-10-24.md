# Исходники CLRS для совместной работы

Рабочая ветка: `codex/clrs-timeweb-20261024`. В ней находятся исходники Flutter,
ресурсы, локализации, тесты и серверная часть `server/timeweb/python-stand/`.
Архив исходников GitLab можно скачать через **Code → Download source code → zip**.
APK декомпилировать не нужно. Пароли, данные пользователей и ключ подписи сюда не входят.

## Ксении

Создавайте свою ветку от этой версии и присылайте изменения через merge request.
Ветка `feed-with-new-design` сохранена отдельно. На 24 октября её вершина —
`0a82ddde2971964ac0803160c3b8a77bbe838f0e`; изменения ленты Ксении находятся,
в частности, в `d4d3606` и `33f96ee`. Они не объявляются объединёнными с этой веткой.
В той ветке также есть изменения оплаты, поэтому переносить её целиком вслепую не следует.

В актуальной конфигурации Timeweb точка входа — `lib/main.dart`, затем
`presentation/screens/auth/timeweb_session_gate.dart` и
`presentation/screens/home/timeweb_home_page.dart` (относительно `lib/`).
Лента и стены Timeweb — `lib/presentation/screens/feed/timeweb_feed_page.dart`;
старые `feed_page.dart`, `profile_wall_page.dart` используют Firebase.
Для доработок нативной ленты используйте `TimewebAppRuntime`,
`timeweb_social.dart`, `timeweb_social_flow.dart` и `timeweb_post_media.dart`:
они сохраняют сессию, права, загрузку фото и подтверждение операций Timeweb.
Возврат Firebase-авторизации в нативный маршрут не требуется.

## Изменения после проверочной сборки 69

- Исправлена немедленная ошибка фото при короткой серии одновременных запросов:
  сервер допускает ограниченное ожидание свободного обработчика. Дополнительная
  проверка 24 октября обнаружила такой же отказ на входе HTTP-сервера;
  `http_runtime.py` теперь допускает до четырёх ожидающих запросов на срок до
  пяти секунд, сохраняя максимум два активных скачивания и доступность других API.
  Отмена, отключение клиента и остановка сервера освобождают очередь.
- Добавлены друзья, входящие/исходящие заявки, принятие, отклонение, отмена,
  удаление и гости. После потери ответа клиент проверяет исходную операцию,
  чтобы не создать повторную заявку.
- В базу Timeweb перенесено 26 267 записей посещений. Исходный архив сохранён.
- Сборка проверяет наличие библиотек Flutter для каждой заявленной архитектуры.

Проверки этих изменений выполнены локально: 70 целевых проверок фото,
44 проверки контактов и связанного серверного поведения, 4 сценария контактов
Flutter, 12 проверок сборочного скрипта. Списки контактов дополнительно проверены
запросами к MySQL. Это не заменяет проверку через опубликованный API.

24 октября дополнительная проверка через настоящий HTTP воспроизвела два отказа
503 из четырёх одновременных запросов; после исправления все четыре получили 200.
23 целевые проверки HTTP, очереди и фото прошли. Проверка кандидата на локальном
сервере с настоящими MySQL/S3 Timeweb также подтвердила вход тестового аккаунта,
чтение четырёх списков контактов и четыре одновременных скачивания фото.
Скачивания заняли 3–6,3 секунды с этого Mac; это подтверждает устранение отказов,
но не мгновенную загрузку и не производительность опубликованного сервера.
На двух существующих тестовых аккаунтах через этот же HTTP-кандидат и настоящую
базу проверены отправка заявки, входящие заявки, принятие, список друзей,
удаление и запись посещения с отображением в гостях. Тестовая дружба удалена,
тестовые сессии закрыты. Пользовательские аккаунты не изменялись.

Старые наборы `test_native_http.NativeHttpTest` и
`test_legacy_private_media_http` не проходят также на исходном `http_runtime.py`
до этой правки (их старые настройки дают 503). Они не включены в число прошедших
проверок; при обновлении тестовых настроек нельзя ослаблять рабочие проверки доступа.

## Сборка и сервер

Инструкция: `TIMEWEB_ANDROID_BUILD.md`. Flutter 3.32.5, JDK 17.
Проверочный APK 70 собран из `b379e2b3e8adf33be1d2f592a78bfaebb3aadb73`:

```sh
python3 tool/build_timeweb.py --mode qa --build-number 70 --target-platform android-arm64
```

Это ARM64 APK с проверочной подписью. Для нового APK задайте следующий свободный
номер; для RuStore нужен исходный ключ уже опубликованного приложения.

На момент подготовки этой передачи серверные исправления фото и контактов
ещё не опубликованы. Таблицы контактов уже созданы; порядок включения API описан
в `server/timeweb/CONTACTS.md`. Перед выкладкой нужно обновить привязанные к коду
серверные настройки штатной процедурой и проверить новый сервер с настоящей
тестовой сессией. Эти настройки хранятся вне Git. Публикация этой ветки сама по
себе не переключает Timeweb и не выпускает приложение в RuStore.
