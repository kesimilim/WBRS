# Incremental source-profile originals

This read-only port serves operator-reviewed original photos captured and transferred after the earlier seven-profile snapshot. It does not modify that snapshot, its verifier, sidecars or ACK. It does not assert a global generation, a consistent final capture, a source barrier or final migration authority.

The current actual addition review artifact contains two disposable source profiles, exactly six root/gallery references and six immutable private S3 copies totalling22812bytes. Their normal source roots, exact typed gallery documents, original source identities, SHA/size/MIME/generation and fresh canonical/private full-byte readbacks already exist. That encrypted evidence is review input; this source patch has not issued a capability, changed SQL data, been deployed or activated.

`verify_profile_photo_delta(raw,key,separate_from=(session,cursor,review))` accepts an at-most64KiB JSON envelope with a separate32byte HMAC key and the domain `clrs-source-profile-photo-delta-readback-v1\0`. The key must differ from the session, cursor and previous review/ACK keys. The exact body has source/policy/build fingerprint, four original evidence digests, target bucket/owner and legacy promotion binding; all readback fields must be true, while final/barrier fields must be false. The digest list is not evidence by itself: the protected issuer must first authenticate the actual source capture, exact target-plan/fresh-SQL readback and actual full/private S3-copy receipts. No issuer or fabricated proof is included here.

The envelope carries1..20 complete reviewed target bundles, limited by the overall64KiB bound. Each contains exact original root/hash, all gallery documents and hashes, and ordered source photos. The existing `source_slots` policy validates complete binary gallery order, original references, primary deduplication and at most20 photos per target. Every target key must derive from the exact source path/generation/contentSHA; arbitrary/quarantine URLs are never public DTO fields. The current two roots remain onboarding/test-incomplete: this port grants no public visibility to them.

`RuntimeProfilePhotoDeltaService` uses the existing current native actor/session store, `_target` visibility checks, exact indexed retained root/gallery SQL and immutable canonical raw comparison. Source project/database/bucket, all retained document bodies/hashes and empty canonical associations must match. Legitimate changes to current profile fields/timestamps are allowed under the current target rules; raw/root/gallery changes refuse. Checks run for descriptors, before fetch, after verified spool and immediately before the first byte. The existing lease verifies full SHA/size/MIME and live object/bucket privacy, uses bounded private anonymous spools and owns cancellation/deadline/disconnect cleanup. Public descriptors and references retain the existing actor/target/context/expiry bindings and wire format.

`create_delta_profile_photos_http(env,legacy_http,snapshot=...)` wraps the already mounted original-version/native composite. Missing capability returns the exact prior HTTP instance; invalid capability refuses; the existing profile-photo gate is unchanged. Construction is lazy and owns its store, spool and predecessor resources. A cohort target with canonical associations must pass the full all-native shape, then resolve to the existing real `RuntimeNativeProfilePhotosService` with original prepare/commit receipts. Mixed, invalid or imported fallback refuses. Targets outside this addition continue through the prior reader.

The new consumer fingerprint covers its two new source files plus the existing captured guard fingerprint. The native writer's ten-file release list is not expanded. A later real app mount changes its actual app binding and requires root to reissue the genuine photo release before deployment; this patch does not bypass that check. Root must review the genuine two-profile addition and independently sign it with a separated key, then mount the factory behind the existing operator guard. No env Boolean creates a capability. Actual final source barrier/cohort remains pending.

Focused local proof uses the real RuntimeMutationStore and existing SQL/private-S3/spool contracts with synthetic SQL/HTTPS. Three new scenarios cover key/domain/readback/refusal/default-off/redaction; actor A→B, hidden/missing target, source/mixed relation changes, revocation after spool and disconnect; and delegation to a real committed native reader with no legacy fallback. The first module run passed the latter two scenarios and exposed a service callback result-shape defect in the first. Returning the required dictionary corrected it; only that affected scenario was rerun and passed. No old suite, live account request, SQL/S3 mutation, secret/config read or activation was performed for this patch.
