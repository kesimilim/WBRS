# Imported meeting operations: source implementation only

The existing `ImportedMeetingAuthority` is the only imported authority. Optional `imported_authority` and exact `reviewed_binding` constructor arguments on the existing join/chat/membership services reuse the same current-token `RuntimeMutationStore`, original operation UUID/hash, atomic receipt and lookup-only unknown-commit contract. Default constructors remain native-only; environment values do not mint a cohort. The production assembler (`app.py`/`runtime_http.py`) is unchanged by this patch. No activation, final barrier, actual SQL, permissions change or live service acceptance is claimed.

Version 1 signed packs retain their original shape/domain and root/roster read behavior. Imported message reads remain unavailable without a version 2 pack. V2 uses `clrs-imported-meeting-final-authority-v2\0`; each reviewed root adds `messages`, an exact contiguous sequence-ordered list of `{messageId,firebasePath,payloadSha256,sequence,senderUid,textSha256,createdAt}`. `finalDelta.messageSetSha256` pins the ordered flattened `[meetingId,pin]` list. The existing signed final-barrier/final-delta assertions, reviewed binding and current source fingerprint remain mandatory. The producer must derive the full canonical child set from actual completed source/readback evidence; a current-root observation or omitted/unsupported message is not a complete message cohort. Unsupported child semantics keep that meeting's imported chat closed. This implementation does not issue a genuine pack.

Each read validates bounded actual `meeting_messages.legacy_raw` against its exact source path/hash and signed canonical pin. Supported old messages are plain text with fields `sender`, `sendByID`, `message`, `type`, `time`, `isRead` only; sender alias precedence matches the existing importer. Quotes, media, per-user deletion and unknown fields are refused. Source UTC timestamps/legacy milliseconds use the existing typed decoder; its explicit exported `createTime` fallback is allowed only for missing/typed-null time. Nonrepresentable nanoseconds and malformed timestamps are refused. No source/raw/private DTO is returned. The original Firestore message ID stays unchanged: 1–191 Unicode scalar characters, at most 764 UTF-8 bytes, no slash/control/DEL/surrogate, excluding `.`/`..`. The GET item still has exactly the existing six fields; original POST receipts retain strict derived `tw-meet-msg-<64hex>` IDs. The Flutter read decoder needs this separately reviewed old-ID allowance before historical messages can render.

Current account, session, profile, foreign organizer/invitee visibility, individual invitation, group access and current kick checks remain in the same transaction. Source `kicked` UIDs stay denied. Original members require their exact immutable source pointer and retain `joined_at=NULL`; only new members outside the original `users` list may carry a genuine native writer marker. Rejoining clears only `left_at` and increments revision. Historical source tail supplies a proven initial read revision floor when imported `meetings.revision` is zero; the first new text atomically CAS-updates the stored revision from its actual old value to the next effective revision. Source root/member/message raw is never rewritten. Whole messages, 30-item/64-KiB pages and actor/meeting/limit/original-300-second cursors remain bounded; imported cursors also bind the current authority fingerprint.

Imported voluntary exit stores its window in a separate `meeting_archive_windows` sidecar, never in source member raw. Source-only DDL is [006_imported_meeting_archive_windows.sql](../server/timeweb/db/006_imported_meeting_archive_windows.sql): matching binary meeting/account IDs and FKs, owner/meeting PK, original owner-operation uniqueness, revision/cutoff/UTC capture and an immutable root/child content digest. The window is CAS-written with membership change and the original leave receipt in one transaction; current account/profile existence and that exact owner's retained receipt prove archive access after exit/rejoin/kick. It grants no live-chat permission. It covers only a new verified Timeweb voluntary exit; old Firebase `removed_meets` archives are not relabeled as this native window. Runtime needs `SELECT,INSERT,UPDATE` on this new table (including locking reads); schema/index checks refuse missing/incompatible setup. Existing root/member/message and receipt privileges remain unchanged. No DELETE, role, grant or DDL execution is performed here.

One new synthetic SQL-shaped scenario uses the actual shared store: imported unknown join time plus new native join, unchanged historical ID/text plus new text, lost exit ACK and original-only restart lookup, exact owner archive cutoff, rejoin, kick denial, immutable raw, malformed cohort and altered source refusals. It is local source/transaction evidence, not production SQL parsing, actual cohort completion or live account/API acceptance. Root must review/apply the DDL/permissions, assemble the same genuine authority into reads and all three mutation services, capture real final source/readback/barrier evidence, and coordinate Flutter old-ID support before activation.
