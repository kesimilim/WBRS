# Native notification center

Read-only current owner projection. Factory `create_runtime_notifications_http(env, store, *, meeting_authority=None)` returns an adapter with `dispatch(environ, *, native_service=None, native_configured=False)`; no new pool or resources, no SQL writes. Root mounts it in the shared dispatcher. Existing native runtime writes + canonical current membership gates apply; missing cursor key/store/native authorizer remains closed.

GET `/v1/runtime/me/notifications?limit=1..30&cursor=opaque` returns exact `{kind:'native-notifications',items,nextCursor}`. Each item is `{id,type,targetKind,targetId,createdAt,read}`. Target kind is chat/meeting/post or null; null target always has null ID. Created timestamp is nullable exact UTC six-fraction Z. Read is nullable bool: native event has no read proof; historical canonical read_at or exact source boolean is retained. No invented unread/default timestamp/name/message body. Source IDs are `e:<positive eventId>` or `n:<source notification ID>`; source ID <=191 Unicode scalars/764 bytes, public prefixed key <=193/770. No slash, control, DEL, surrogate or dot-only IDs.

The indexed list is explicitly **native event_id DESC, then historical created_at DESC / notification_id ASC / NULL last**, not a combined chronological list. At most three raw records per page (plus one lookahead) keep the response under 64 KiB. Own outgoing/unsupported native events can produce an empty sparse page with an active nextCursor. Cursor is opaque, current UID/limit/purpose bound, original 300s expiry and initial event + notice anchors retained. No cursor persists to disk. No total/unread count or mark-read mutation is implied.

GET `/v1/runtime/me/notifications/{id}` accepts no query or body and returns one source-bound item only after fresh current target resolution. Missing/removed/unrecognized target is healthy-owner 404 `notification_unavailable`; bad/revoked native actor is 401; invalid cursor/body/query 400; unavailable authority/projection 503. Chat resolves current canonical pair, meeting current active native/imported authority when genuinely injected, post current published post + active author. Old source records alone grant no live capability. Shared read_authenticated checks current actor/session before and after the bounded SQL transaction.

Push worker must include `notificationId:'e:'+validated original eventId`. Client resolves that source with fresh GET before routing; no fallback to an unproven chat/meeting ID. Existing readEvents delta polling is unchanged. Genuine imported meeting authority is optional and closed without its current capability.
