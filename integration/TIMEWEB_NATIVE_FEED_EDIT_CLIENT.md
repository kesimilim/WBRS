# Спецификация API: Редактирование постов и мультимедиа в Timeweb

Этот документ определяет требования к серверной части Timeweb Runtime для полноценной поддержки редактирования публикаций, работы с множеством изображений и удаления постов.

---

## 1. Публикация поста с несколькими изображениями (`publish`)

### Текущее состояние:
Эшен `TimewebSocialAction.publish(text)` передает только текстовое содержимое.

### Требуемый формат полезной нагрузки (Payload):
```json
{
  "kind": "publish",
  "text": "Текст публикации...",
  "mediaIds": ["media_id_1", "media_id_2"]
}
```
### Требования к серверу:
- Принимать опциональный массив идентификаторов медиафайлов `mediaIds` (до 10 изображений).
- Связывать загруженные бинарные файлы (через S3 / photo upload растер) с создаваемым ID публикации.

---

## 2. Редактирование публикации (`update_post`)

### Назначение:
Позволяет пользователю изменять текст и прикрепленные изображения ранее опубликованного поста. На стороне клиента добавлена кнопка редактирования (в меню 3 точки), а в редакторе выводится уведомление о разработке до реализации на бэкенде.

### Требуемый формат полезной нагрузки (Payload):
```json
{
  "kind": "update_post",
  "postId": "tw-post-...",
  "text": "Обновленный текст публикации...",
  "keepImageUrls": ["https://..."],
  "newMediaIds": ["media_id_new"]
}
```
### Требования к серверу:
- Проверять права доступа (автор публикации либо администратор/модератор).
- Обновлять текстовое содержимое записи в БД.
- Синхронизировать сохраненные (`keepImageUrls`) и новые (`newMediaIds`) медиа-вложения.
- Возвращать подтверждение успеха либо ошибку доступа (`403 Forbidden`).

---

## 3. Удаление публикации (`delete_post`)

### Требуемый формат полезной нагрузки (Payload):
```json
{
  "kind": "delete_post",
  "postId": "tw-post-..."
}
```
### Требования к серверу:
- Выполнять мягкое или жесткое удаление публикации в базе данных при запросе от автора поста или модератора.
