# Current-visible native profile photos

This isolated change completes the existing profile-photo DTO/routes for another current visible native profile. It does not mount or enable routes, create credentials, change IAM/SQL, or establish live provider readiness. Baseline is dd9409f99efcc5e84f3abc5f1e92fdeb4d510d66; the actual checkout is unchanged by the artifact.

Previously `profile_photo_branch` sent every target other than the current actor to the imported reader without native classification; native `_context` additionally required actor==target and used actor-owned gallery/receipts. New native uploads cannot pass the imported storage/source proof, so public native photos were unavailable despite ready current associations.

The selector now executes the existing current `read_authenticated` transaction, exact active actor and target lookups, and `_target` visibility before and after classifying the target gallery. Fully imported galleries continue through the existing legacy reader and its full proof. All-native galleries use the native reader; malformed/mixed relations refuse without fallback. Empty native galleries remain empty and subject to the same target visibility.

Native `_context` retains the current actor/session proof and actorHash but loads the target owner's complete <=20 compact gallery, current profile stamp, original successful commit and exact prepare receipts. Shared `photo_identity`/`photo_record` validation binds MID/key and provenance to target UID+original prepare UUID. It checks target visibility before and after; returned reference/cursor still bind current actor, exact target, complete context and <=60-second expiry. UID ownership is not inferred from a public client boolean or supplied object key.

DTO and streaming interfaces are unchanged. The existing verified anonymous spool, full <=5MiB hash/size/MIME/raster validation, live bucket/object privacy and current target/context guard remain required before the first byte and HTTP200. Actor/session revocation returns401; hidden/disabled/deleted/incomplete target returns404 without logging out a healthy actor. References minted for actor A fail under B. No target source/raw/email/role/key/URL is added to responses.

Production changes only `runtime_native_profile_photos.py`. S3/core/factory/app/runtime HTTP/old imported readers and flags are unchanged. Existing release witness source/build fingerprint includes this reader, so a deployment of changed bytes requires an exact newly reviewed release attestation; this patch does not manufacture one, extend the pilot300s proof, or activate anything.

Local evidence: one new module, four cases PASS0.448s, uses actual current store/native reader/S3 adapter/Pillow worker with synthetic SQL+HTTPS only. It covers foreign visible byte output; hidden/disabled/deleted/incomplete target and late visibility refusal with no200; A→B reference binding and actor revoke after spool; mixed/wrong owner/wrong original receipt without fallback. Only the affected old composite case rerun, PASS0.106s; its fake legacy target is now a visible imported relation rather than a hidden empty profile. The small fixture supports explicit invisible_until. No old suite, user/config/credential read, TCP/cloud/SQL, build or activation was performed.
