# Captured current profile photo versions

This reader serves the reviewed fresh source associations for six newly imported profiles and one changed avatar. Its fixed generation is a verified staging generation. It does **not** claim that Firebase writers have stopped, that a final delta is complete, or that public cutover has happened.

The existing imported reader, native upload reader, original `legacy_raw`, `legacy_documents`, `legacy_storage_objects`, `media_objects` and `profile_photos` stay intact. Two additive sidecars store fourteen actual immutable object versions and seven complete current root/gallery association bundles. The captured seven bundles describe ten originals. No thumbnail, stock photo, owner, ordinal or missing reference is guessed.

The source root and every gallery document retain their literal values and hashes. Gallery order uses exact binary source document IDs, includes omitted valid blank URLs in the proof, and caps twenty returned originals. A primary/gallery alias is deduplicated only when both literals use the exact Firebase Storage HTTPS bucket/path and only `alt=media` plus `token`; an explicit generation selector or any other alias is rejected. Object generation and actual bytes come from the separate authenticated current Storage capture/copy evidence.

An original can legitimately occur in multiple source profiles. Its association is authorized by the exact current target root/gallery reference; the reader assigns no guessed exclusive `media.owner_uid`. The complete observed reference cohort stays in the encrypted plan and SQL bundle. A foreign actor cannot address a file by path, key, hash or another UID alone.

Changed/new objects use the new content/generation-derived immutable key and the actual fourteen-object copy receipt. Unchanged objects require the authenticated original full media acknowledgement plus exact current generation/size/MD5/CRC/MIME agreement with the locked retained Storage row. Their old media status and owner are not rewritten. Every fetch still reads the entire private S3 object, verifies length/SHA/MIME into an anonymous private spool, and checks private bucket/API/ACL before and after download and again before its first output byte.

Descriptor and bytes interfaces are the existing `/v1/runtime/people/{uid}/photos` and `/photos/content`. The existing opaque actor/target/context-bound sixty-second references, thirty-descriptor/64KiB page, eight-MiB original bound, two spool slots, expiry hard-close and disconnect cleanup are reused. Current native session, active actor, target visibility, stable canonical UID/account identity and immutable raw hash, current profile/session/visibility before and after each proof, original associations and exact sidecar hashes are checked before/after preparation and before first byte. A stale or invalid reviewed member refuses without falling back to its old avatar. A legitimate profile edit, registration change or online timestamp does not invalidate retained photos; current full guards still bind each short-lived descriptor, so an older descriptor refuses after a change. A nonempty replacement gallery delegates only after exact native gallery validation to the ordinary native reader, which proves original prepare/commit receipts. Mixed/invalid replacements refuse without imported fallback. Empty canonical galleries remain versioned. Non-cohort targets use the existing reader.

`create_versioned_profile_photos_http(env, legacy_http, snapshot=None)` returns the identical existing adapter by default. A supplied unregistered capability fails closed. `verify_photo_versions(raw, operator_key)` validates a bounded domain-separated HMAC acknowledgement bound to the fixed genuine source/copy generation, exact seven/fourteen row hashes and source fingerprint. It requires actual fresh-readback/verified-copy fields and explicitly `sourceBarrierVerified=false`; a Boolean or loose environment digest cannot issue it. The production factory also independently revalidates the genuine original media acknowledgement and uses only the existing dedicated read credential. A root assembler must inject the verified capability; this source artifact does not enable a flag or mount the app.

The private executor inserts only the two sidecars after locking the unchanged account/profile/gallery baselines. It writes and fsyncs the encrypted original-before/prepared receipt before COMMIT. Unknown COMMIT outcomes reconcile that original receipt through a new read-only connection and never resend INSERT. A fresh full readback issues the protected runtime acknowledgement. Existing paid `clrs_staging` is used; no new database, grant or storage resource is requested.

Five focused local cases cover genuine store/session checks with injected SQL/HTTPS, current and shared old objects, exact token-only aliases, false capability/default-off, mixed galleries, A-to-B identity mismatch, hidden targets, tampering, actor revocation after spool, pre-first-byte privacy and disconnect cleanup. These are local source checks, not real user HTTP proof. Previous imported/native media suites and full archive scans were not rerun.
