# Восстановление полей импортированных профилей Timeweb

Первоначальный импорт сохранил оригинальные анкеты в `profiles.legacy_raw` и `legacy_documents`, но пропустил 11 отдельных столбцов профиля. Из-за этого сохранённые возраст, рост, описание и другие сведения нельзя было получить из нормализованного профиля. Новый backfill заполняет только пропущенные столбцы при подтверждённом совпадении с исходной записью. Это отдельный этап переноса данных, а не доказательство завершения всей миграции приложения.

## Какие поля меняются

Преобразование выполняет существующий `server/timeweb/project-profile-details.mjs`: повторной реализации правил нет. Строки сохраняются без обрезки, подмены, исправления формата или нормализации Unicode. Исходные значения остаются в архивных JSON.

| Поле Firestore в `legacy_raw.fields` | Целевой столбец |
| --- | --- |
| `age` | `age` |
| `rost` | `height_cm` |
| `about` | `about_text` |
| `hobbi` | `interests_text` |
| `deti` | `has_children` |
| `pol` | `gender` |
| `relationStatus` | `relationship_status` |
| `countryCode` | `country_code` |
| `region` | `region` |
| `languageCode` | `language_code` |
| `secondaryGroup` | `secondary_group` |

Помимо этих 11 столбцов обновляется только `profiles.updated_at`: новый штамп строго больше прежнего. Он блокирует сохранение профиля запросами со старой версией, в том числе если значения совпали после отката. Исходные `createTime` и `updateTime`, включая наносекунды, остаются в `legacy_raw` без изменения.

`profile_details_saved` и `registration_complete` проверяются по тому же проектору, но не обновляются. Backfill не меняет основные поля имени, страны, города и основной группы, `test_result`, видимость, время последнего посещения, аккаунты, роли, состояние блокировки, баланс, подарки, оплату, медиа или архивные таблицы. Новых DDL, HTTP‑методов и флагов включения здесь нет.

## Условия допустимого изменения

Каждая порция содержит не более 100 профилей. Размер возвращаемого профиля и исходного payload ограничен 64 КиБ; слишком большая или повреждённая запись получает отказ, значения не обрезаются.

Перед подготовкой плана и повторно перед записью проверяются:

1. Подтверждённые источник и целевая БД `clrs_staging`; строгий MySQL 8.4 и `utf8mb4`. Подключение вызывающей программы должно проверять сертификат CA и имя сервера и иметь ограниченное время операций.
2. Архивная запись связана с профилем только через точный путь `users/{uid}`, его SHA‑256, `collection_path = users` и исходный `document_id`. Совпадение email, имени или одного хэша не заменяет эту проверку.
3. `legacy_raw` глубоко равен `legacy_documents.encoded_payload`; канонический `payloadHash` обеих записей равен сохранённому `payload_sha256`.
4. Вся анкета представима текущим JS‑проектором. Неподдерживаемые значения пропускаются без округления, исправления или частичного переноса остальных полей этой анкеты.
5. Все 11 целевых столбцов по‑прежнему равны `NULL`.
6. Основные поля, два флага и `updated_at` совпадают с исходным импортом. `test_result` остаётся пустым объектом, `invisible_until` и `last_online_at` — `NULL`. Следы последующих изменений исключают профиль из переноса.

В транзакции записи блокируются источник и профили, затем повторно сверяется весь рассмотренный план. `UPDATE` передаёт значения параметрами и дополнительно проверяет точный UID, прежний штамп и все 11 `NULL`‑столбцов. После всех обновлений одним чтением всей порции проверяются новые значения, свежие штампы и сохранность остальных данных. Любое несовпадение отменяет порцию целиком.

## Подготовленная запись восстановления и откат

После проверки изменений и до `COMMIT` публикуется отдельный зашифрованный CLRSX2‑файл со снимками `before`/`after`, привязкой к источнику, плану и операции. Файл находится вне репозитория в закрытом каталоге; синхронизируются и файл, и запись каталога. Ошибка публикации отменяет транзакцию. В открытые результаты попадают только счётчики, причины пропуска и хэши плана — без UID и пользовательских значений.

Состояние файла `prepared` подтверждает подготовку операции и само по себе не доказывает успешный `COMMIT`. При потере ответа на `COMMIT` результат считается неизвестным. Автоматического повторения нет: `verifyProfileDetailsBackfillReceipt` на новом соединении сравнивает все строки со снимками и подтверждает либо `committed_verified`, либо `not_committed_verified`. Последующие изменения или смешанный результат требуют отдельной проверки.

Откат разрешён только по прочитанному зашифрованному файлу восстановления. До первого `UPDATE` проверяются все строки порции: точные значения `after`, штамп результата переноса, исходный raw/hash и неизменённые основные поля, флаги, тест и видимость. Даже одно последующее изменение запрещает откат всей порции. Откат возвращает 11 прежних значений и выдаёт свежий `updated_at`; старый штамп не восстанавливается. До его `COMMIT` сохраняется отдельный зашифрованный файл `prepared` с операцией `restore`. Неизвестный исход отката проверяется по этому новому файлу на новом соединении.

## Подтверждённые результаты на 2 октября 2026

Полный READ ONLY‑проход исходных полей в `clrs_staging` охватил **6031 из 6031 профилей**, 61 порцию максимум по 100 строк. TLS проверял CA и имя сервера. Транзакция использовала согласованный снимок и завершилась `ROLLBACK`; записей в БД, изменений схемы и облачных изменений — **0**. Чтение возвращало только 13 пар «наличие ключа + типизированное значение» и передавало их локально текущему JS‑проектору; UID и оригинальные значения не печатались и не сохранялись в открытом виде.

Проектор принял **5927** анкет и отказал **104**. Это статистика представимости исходных значений, **не статистика фактической допустимости backfill**: основные поля, штампы и остальные защитные условия в этом проходе ещё не проверялись.

| Первый отказ проектора в анкете | Количество |
| --- | ---: |
| Рост: неподходящий формат целочисленной строки | 67 |
| Возраст: неподходящий формат целых цифр | 17 |
| Возраст: значение за диапазоном схемы | 16 |
| Рост: значение за диапазоном схемы | 4 |
| **Всего** | **104** |

Причины учитываются по одному первому отказу на анкету. Для 104 анкет требуется отдельное решение по исходным значениям; этот backfill их не исправляет. Агрегированный результат находится в приватном файле `profile-details-readiness-full-proof-20261002.json`, в нём нет пользовательских значений.

Код `server/timeweb/profile-details-backfill.mjs` проверен 11 целевыми синтетическими тестами из `server/timeweb/test/profile-details-backfill.test.mjs`: перенос и откат, неизменность защищённых данных, конфликт версий, отказ при последующей правке, зашифрованная публикация до `COMMIT`, неизвестный исход переноса и отката, отказ публикации файла, ограниченное чтение. Эти тесты не заменяют подтверждение реального изменения данных.

## Подтверждённый перенос в `clrs_staging`

После отдельного READ ONLY‑прохода всех защитных условий был рассмотрен и применён код из коммита `4fcc18b`. Проверено **6031** профилей: **5927** допущены к записи, **104** пропущены по тем же четырём причинам несовместимого возраста или роста. Таким образом, в этом запуске дополнительная проверка исходной записи, основных полей, флагов и штампов подтвердила допустимость изменения всех 5927 представимых анкет.

Все **61 порция** завершились `committed_and_fresh_verified`: после `COMMIT` результат каждой порции проверен через **новое соединение**. Подтверждены записанные значения и свежие штампы для **5927 профилей**. Агрегированный приватный файл `profile-details-backfill-20261002-strict/live-proof.json` имеет состояние `all_reviewed_batches_committed_and_verified` и `complete = true`; здесь `complete` относится только к этому рассмотренному переносу допустимых профилей.

Подключение использовало проверку сертификата CA и имени сервера. Вызывающая программа сохранила существующие режимы `sql_mode` и добавила строгий режим только для своих сессий; глобальные режимы сервера не менялись. Подготовленные файлы с данными для восстановления зашифрованы и находятся вместе с ключами вне Git, в закрытом каталоге с правами `0700`; файлы имеют права `0600`. Пользовательские значения в открытые результаты не выводились.

Этот запуск не менял схему, архивные raw‑данные, аккаунты, роли, баланс или видимость и не включал новые API. **104 неподдерживаемые анкеты пропущены целиком**, их исходные значения сохранены без исправления. Для них остаётся отдельное решение по данным. Подтверждение этого backfill не означает полного переключения приложения на Timeweb или завершения всей миграции; общий переход и остальные сценарии требуют собственных подтверждений.
